# Сайт трекера трат — рабочая папка и деплой

Отсюда собирается и деплоится то, что работает на Fly.io. Второй бот (почтовый,
УКФ) живёт в этом же контейнере, поэтому его исходники тоже здесь.

- Адрес сайта: **https://expense-bot-vadim.fly.dev**
- Приложение на Fly: `expense-bot-vadim` (регион fra, одна машина `late-sun-9480`,
  том `ukf_data` на `/data`, ~$32/год)
- Соседняя папка `/home/q/expense-bot` — это телеграм-бот расходов, он же
  репозиторий на GitHub. Он **не** деплоится, и деплоить из него нельзя:
  там нет `fly.toml`, и старый конфиг заменил бы сайт ботом.

## Что где лежит

| Путь | Что это |
|---|---|
| `web/` | серверная часть: FastAPI (`main.py`), авторизация (`security.py`), расчёт плана (`plan.py`) |
| `frontend/` | интерфейс: Vue 3 + Vite + Tailwind, собирается в `web/static` |
| `supervisor.py` | запускает в контейнере два процесса: `web` и `mailbot` |
| `mailbot/` | почтовый бот УКФ (рабочая версия для контейнера) |
| `mailbot_src/` | исходный вариант почтового бота (для сверки) |
| `mailbot_data/` | локальная копия-бэкап данных почтового бота (в git не входит) |
| `db.py`, `budget.py` | **общий** код: база и арифметика плана (копии из папки бота) |
| `fly.toml`, `Dockerfile`, `requirements.txt` | конфиг сборки и запуска на Fly |
| `.webtest/` | локальные прогоны и тесты (в git и в образ не входят) |

## Локально посмотреть

```bash
/home/q/expense-site/.webtest/run_local.sh     # → http://127.0.0.1:8080
```

Работает на копии боевой базы (`.webtest/expenses.db`), боевые данные не
затрагиваются. Логин `vadim`, пароль — в `.webtest/.password`.
Пароль локального превью **не** совпадает с боевым.

Проверки:

```bash
.venv-web/bin/python .webtest/api_test.py     # API на локальной копии (можно гонять всегда)
APP_PASSWORD='…' .venv-web/bin/python .webtest/prod_test.py   # боевой сайт, обратимые записи
```

## Деплой

```bash
cd /home/q/expense-site
export PATH=/home/q/.fly/bin:$PATH
flyctl deploy --remote-only
```

Фронтенд собирается внутри Docker-стадии — локально `npm run build` перед
деплоем не нужен. Если собираешь локально только для проверки:
`npm --prefix frontend run build`.

После деплоя имеет смысл прогнать `prod_test.py` и проверить, что машина
`started`, а health-check `1/1` (`flyctl machine list -a expense-bot-vadim`).

## Про `db.py` и `budget.py`

Это единственные файлы, которые есть в обеих папках. Здесь лежит **актуальная**
версия: сайт импортирует их из корня этой папки, и именно они попадают в образ.
В `/home/q/expense-bot` остались их копии как состояние GitHub-репозитория
(бот — легаси, в проде не запущен).

Правило: правим здесь. Проверить, не разъехались ли копии:

```bash
scripts/diff-with-bot.sh
```

## Git

В этой папке свой локальный git-репозиторий **без remote**: он нужен только
чтобы откатить случайное удаление (`git checkout -- путь`). На GitHub ничего
отсюда не уходит.

`.webtest/prod-dump.db` — снимок боевой базы от 29.10.2026, на нём гоняются
тесты. Свежий снимок: `flyctl sftp get -a expense-bot-vadim /data/expenses.db .webtest/prod-dump.db`
